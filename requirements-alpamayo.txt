# Alpamayo probe environment — MUST be a separate venv from .venv-openvla.
#
# This is not a preference. OpenVLA's trust_remote_code files target
# transformers 4.40.x (hard-pinned in requirements-openvla.txt, and a newer
# accelerate breaks its 4-bit load), while Alpamayo needs the 4.57 era and
# torch >=2.8. The two cannot share an interpreter.
#
# ---------------------------------------------------------------------------
# DO NOT install torch / transformers / accelerate from here.
# ---------------------------------------------------------------------------
# An earlier version of this file floored them (`transformers>=4.57.1`,
# `torch>=2.8`). pip resolved that to transformers 5.17.0 and torch 2.14 with
# CUDA 13 wheels — i.e. it reproduced, in a brand new venv, the exact
# transformers-5.x skew that makes OpenVLA's remote code fail, and pulled a CUDA
# stack that need not match the host driver. Version skew of precisely this kind
# already cost this project a 15GB download (see docs/DESIGN.md §7).
#
# The upstream project (github.com/NVlabs/alpamayo) ships a lockfile with the
# versions it was actually tested against. Let IT own the heavy stack:
#
#   pip install git+https://github.com/NVlabs/alpamayo      # brings its own pins
#
# or, closer to what upstream documents:
#
#   uv venv .venv-alpamayo && source .venv-alpamayo/bin/activate && uv sync
#
# Then verify before trusting anything:
#
#   python -c "import torch, transformers; print(torch.__version__, transformers.__version__)"
#
# transformers should land in the 4.57.x era. If it reports 5.x, the resolver
# has drifted past what the model's code expects — pin it down before debugging
# anything else, the same way requirements-openvla.txt pins 4.40.1.
#
# INSTALL ORDER MATTERS — alpamayo_r1 depends on flash-attn, whose setup.py
# imports torch at BUILD time. pip's build isolation hands it a fresh env with
# no torch, so a plain `pip install git+...` dies with:
#     ModuleNotFoundError: No module named 'torch'
# ...while "getting requirements to build wheel" for flash-attn. Install torch
# first, then flash-attn with isolation off, then the model package:
#
#   nvidia-smi | head -4          # read the driver's CUDA version
#   pip install "torch>=2.8,<2.10" --index-url https://download.pytorch.org/whl/cu128
#   python -c "import torch; print(torch.cuda.is_available())"   # must be True
#   MAX_JOBS=4 pip install flash-attn --no-build-isolation       # 20-60 min
#   pip install git+https://github.com/NVlabs/alpamayo --no-build-isolation
#
# MAX_JOBS caps parallel nvcc; unbounded it eats tens of GB of RAM, and this is
# a shared machine. Prebuilt wheels (matching torch/CUDA/cp312/cxx11abi) at
# github.com/Dao-AILab/flash-attention/releases skip the compile entirely.
#
# Worth checking before committing an hour to the build: flash-attn is a
# declared dependency that the INFERENCE path may not actually import.
#   pip install git+https://github.com/NVlabs/alpamayo --no-deps --no-build-isolation
#   pip install colorlog einops transformers accelerate
#   python -c "from alpamayo_r1.models.alpamayo_r1 import AlpamayoR1; print('ok')"
#
# flash-attn also needs real scratch space — set TMPDIR onto the NAS (below) or
# the build dies with [Errno 28] partway through.
#
# ---------------------------------------------------------------------------
# DISK: set these BEFORE any pip command on this box
# ---------------------------------------------------------------------------
#   source /media/nas_mount/AnuragMandke/env.sh
# which must export at least:
#   export TMPDIR=/media/nas_mount/AnuragMandke/tmp
#   export PIP_CACHE_DIR=/media/nas_mount/AnuragMandke/pip-cache
#   export HF_HOME=/media/nas_mount/AnuragMandke/hf
# `/` and the shared home /home/research2 are both too small; pip defaults to
# both and fails with [Errno 28] No space left on device.
#
